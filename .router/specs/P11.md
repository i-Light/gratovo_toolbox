# P11 spec: the Find IPC and main's find service (3e-1)

Tier N (`router-normal`). Written by the lead (H) on 2026-10-21. The contracts below are fixed;
ask the lead before changing one. Read first: `CLAUDE.md`, `docs/conventions.md`,
`.router/PLAN.md` (D2, D3, D5, D9, D12 and the contracts), `apps/desktop/src/main/pipeline/`
(`protocol.ts`, `supervisor.ts`, `python-path.ts`, `logs.ts`, all done in P10), and how an existing
domain is wired end to end: `packages/ipc/src/{channels,events,bridge,sync}.ts`,
`apps/desktop/src/main/{handlers,index}.ts`, `apps/desktop/src/main/account/account.ts`.

## Decisions (lead)

1. **Where the queue and rules live (changes D12).** The data source has no settings API, so the
   queue, `at` and the rules live in `find.json` in the pipeline's own data folder:
   `<userData>/example-pipeline/find.json` when the account is `unconfigured` (example data),
   `<userData>/pipeline/find.json` when `signed-in` (live). Example and live stay apart, as D12
   wanted. Main owns the file; write it atomically (temp file, then rename). A missing or invalid
   file means the defaults. `pipeline.db` sits in the same folder and belongs to Python.
2. **Default rules** (the owner's `legacy/data/run_config.json`): countries
   `["AU","CA","GB","IE","NZ","US"]`, perKeyword 200, sortBy `upload_date`, resultsType `video`,
   autoClean `{enabled: true, minSubscribers: 50000, maxSubscribers: 2000000, belowMin: "sweep",
   aboveMax: "delay", label: "inactive"}`.
3. **Error text is a code.** `FindState.run.error` is a code, never Python's text; the page maps
   codes to its own strings (all user-facing strings in one place).
4. **Worker id.** Add `findContext(): { mode: "example" | "live"; workerId: string } | null` to
   `Account`: `unconfigured` → `{mode: "example", workerId: "example"}`; `signed-in` →
   `{mode: "live", workerId: <the live copy's user id>}`; otherwise null. Nothing else in the
   account changes.
5. **Proxies and gateways** come from the secret store: `pipeline.proxies` and `pipeline.gateways`,
   each a JSON list of URL strings. Missing or not a list of strings → `[]`. They go only into the
   start message's `secrets`, never into state, events or logs. (The Settings section to edit them
   is step 9.)
6. **Edits while running.** `find:add` is allowed while running (it appends; the running job keeps
   its own list). `find:remove` and `find:start-at` answer `{ok: false, problem: "running"}`.
7. **Sign-out and quit.** `auth:sign-out` awaits `find.shutdown()` before `account.signOut()`. On
   `before-quit`, if the supervisor is running: `preventDefault()`, await `supervisor.shutdown()`,
   then `app.quit()` again (guard against looping).

## Contract: `packages/ipc/src/find.ts` (export it from `index.ts`)

```ts
// The same shape as main's `rulesSchema` (apps/desktop/src/main/pipeline/protocol.ts). Copy it;
// a test in main checks z.toJSONSchema(findRulesSchema) equals z.toJSONSchema(rulesSchema).
export const findRulesSchema;            // { countries, perKeyword, sortBy, resultsType, autoClean }
export const findKeywordStates = ["queued", "running", "done", "failed"] as const;
export const findRunStates = ["ready", "running", "stopping", "paused", "done", "failed"] as const;
export const findErrors = ["no_youtube_key", "blocked", "quota", "network", "crash"] as const;

export const findStateSchema = z.strictObject({
  queue: z.array(z.strictObject({
    keyword: z.string().min(1).max(200),
    state: z.enum(findKeywordStates),
    found: count, kept: count,               // count = int 0..1_000_000
  })).max(500),
  at: z.number().int().min(0).max(500),      // the next keyword to run
  rules: findRulesSchema,
  run: z.strictObject({
    state: z.enum(findRunStates),
    found: count, kept: count, swept: count,
    error: z.enum(findErrors).nullable(),
  }),
  log: z.array(z.strictObject({
    at: z.number().int().nonnegative(),      // ms
    level: z.enum(["info", "warn", "error"]),
    text: z.string().max(500),
  })).max(200),                              // oldest first, newest 200
  kept: z.array(z.strictObject({
    channelId: z.string().regex(/^[A-Za-z0-9_-]{1,64}$/),
    name: z.string().min(1).max(200),
    handle: z.string().min(1).max(200).nullable(),
    subscribers: count.nullable(),
    medianViews: count.nullable(),
    country: z.string().regex(/^[A-Z]{2}$/).nullable(),
    keyword: z.string().min(1).max(200),
  })).max(100),                              // newest first
});
export type FindState = z.output<typeof findStateSchema>;
```

Channels (add to `channels.ts`; requests are `z.strictObject`):

| Channel | Request | Response |
|---|---|---|
| `find:state` | `{}` | `FindState` |
| `find:add` | `{keywords: string[]}` (1..500 items, each 1..200 chars before trimming) | `{added: count, skipped: count}` |
| `find:remove` | `{index: int 0..499}` | `{ok: true} \| {ok: false, problem: "running"}` |
| `find:start-at` | `{index: int 0..499}` | `{ok: true} \| {ok: false, problem: "running"}` |
| `find:start` | `{}` | `{ok: true} \| {ok: false, problem: "no_keywords" \| "running" \| "no_youtube_key" \| "no_python"}` |
| `find:stop` | `{}` | `{}` |

Event: `find:changed` with payload `findStateSchema`; add it to `appEvents` (`events.ts`) and to
`appEventNames` (`bridge.ts`); the existing test keeps the two equal.

`find:add` trims each keyword, drops empty ones, and skips one already in the queue or earlier in
the same request (case-insensitive), or past 500 entries. `find:remove` out of range is
`{ok: true}` and changes nothing; removing an entry before `at` moves `at` back by one.
`find:start-at` clamps to the queue length.

## Main: `apps/desktop/src/main/find/`

- `find-store.ts`: `readFindFile(folder)` → `{queue, at, rules}` (defaults when missing or
  invalid; a `running` entry read back is `queued`), `writeFindFile(folder, value)` (atomic).
- `results.ts`: `readKept(dbPath, limit = 100)` opens `pipeline.db` **read-only** with
  `node:sqlite` (`new DatabaseSync(path, { readOnly: true })`); a missing file → `[]`. Query:
  `SELECT c.channel_id, c.name, c.handle, c.subscribers, c.median_views_last_30, c.country,
  (SELECT k.keyword FROM channel_keywords k WHERE k.channel_id = c.channel_id ORDER BY
  k.discovered_at DESC LIMIT 1) AS keyword FROM channels c WHERE c.videos_fetched_at IS NOT NULL
  ORDER BY c.videos_fetched_at DESC LIMIT ?`. `subscribers` is TEXT ("48200" or "Hidden"): a plain
  number or null. A row with no name uses the handle, then the channel id. Close the database after
  each read. The test builds a small `pipeline.db` itself with just the columns it reads.
- `find-service.ts`: `createFindService(deps)` with deps `{ supervisor: PipelineSupervisor,
  account: { findContext(); teamKeys: { youtubeKey(): Promise<string | null> } }, secrets:
  Pick<SecretStore, "get">, userData: string, emit: (state: FindState) => void, now: () => number,
  throttleMs?: number /* 250 */ }`, returning `{ state(), add(), remove(), startAt(), start(),
  stop(), shutdown() }` that the handlers call.
  - `start()`: refuse `running` if the supervisor runs; `no_keywords` if `at >= queue.length`;
    live without a key → `no_youtube_key` (a key lookup that throws → also `no_youtube_key`, and
    log it with `console.error` naming no value); `no_python` from the supervisor. The start
    message: `source` = mode, `dataDir` = the folder, `worker` = workerId, `job` = `{kind:
    "search", keywords: <every queue keyword>, startAt: at, rules}`, `settings: {}`, `secrets:
    {youtubeKey: live ? key : null, proxyUrls, gatewayUrls}`. On ok: `run` = `{state: "running",
    found: 0, kept: 0, swept: 0, error: null}`, log cleared.
  - Messages: `keyword started` → that entry `running`; `keyword done` → `done` with its
    found/kept, `at` = index + 1, `run.found += found`, write the file; `keyword failed` → `failed`;
    `channel` kept → `run.kept += 1` and prepend to the kept list (cap 100), swept →
    `run.swept += 1`; `log` → append `{at: now(), level, text}` (cap 200, drop oldest).
  - Exit: `ended` → `at` = `end.at`; run state `done` / `paused` (end `stopped`) / `failed` with
    `error` = the end's code (`bad_start` → `crash`). `failed` with reason `killed` after a stop →
    `paused`; any other failed exit → `failed`, `crash`. Entries still `running` go back to
    `queued`. Re-read the kept list from `pipeline.db`. Write the file.
  - `stop()`: run state `stopping`, `supervisor.stop()`.
  - `state()` builds a fresh `FindState`; when no run has happened since launch the run is
    `{state: "ready", 0, 0, 0, null}` and `kept` comes from `pipeline.db`.
  - Every change calls `emit` at most once per `throttleMs` (trailing call keeps the newest), and
    user actions (`add`, `remove`, `startAt`, `start`, `stop`) emit at once.
  - The mode can change (sign-in, sign-out): read `findContext()` on every call; a null context
    makes `state()` and the edits throw "No data is open." (as `handlers.ts`'s `openSource`).
- `handlers.ts`: the six channels, delegating to the find service; `HandlerContext` gains `find`.
- `index.ts`: build the supervisor (`spawn` from `node:child_process` with `stdio: "pipe"` and
  `windowsHide: true`; `findPython({packaged: app.isPackaged, appPath: app.getAppPath(), exists:
  existsSync})`; `pipelineEnv(process.env)`; logs in `join(userData, "logs")`), the find service
  (emit through the existing event sender's `find:changed`), and decision 7.
