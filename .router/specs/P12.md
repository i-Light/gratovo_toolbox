## What to build

The **Search** tab of the Find screen (`/find`, tab `search`), as the prototype lays it out: a
two-column grid, **Keywords** on the left, and on the right **Live run** then **Rules** then a
**Kept** list. The other Find tabs (Review new, Gallery, Contacts) stay placeholders.

- **Keywords**: heading with "N · M done"; the list (number, keyword, a check when done; on the
  right "found · kept" with the yield bar for done ones, "searching…" with a spinner for the
  running one, "next up" for the entry at `at`, "queued" for the rest, "failed" for a failed one);
  per row **Start here** (a queued row that isn't next, while not running) and **Remove** (not
  while running); under the list the textarea "Paste keywords, one per line. Duplicates are
  skipped." with **Add keywords** and the hint (count ready / "Commas work too."). Split on
  newlines and commas. After adding, say how many were added and skipped.
- **Live run**: the headline by state (running: Searching "<keyword>"; done: Finished ·
  everything found is saved; ready: Not started yet · N keywords queued; paused: Paused at
  keyword N · everything found is saved; failed: Stopped at keyword N · everything found is
  saved; stopping: Stopping…), "done/total"; the meter of keywords searched; three mini stats:
  channels found, kept by your rules, archived by rules (`run.found`, `run.kept`, `run.swept`);
  for a failed run, a callout with the message for `run.error`; the run log (`role="log"`,
  `aria-live="polite"`, time and text per line, scrolled to the newest, the empty text "The log
  fills in as each keyword is searched."); the buttons: running → **Pause** (calls `find:stop`);
  otherwise **Start the search** / **Resume at keyword N** / **Try again from keyword N** (calls
  `find:start`); no button when every keyword is done.
- **Rules** (read-only in 3e-1; editing is step 5): tags for the countries, "N channels per
  keyword", and the auto-clean band ("Archive under 50K subscribers", "Leave over 2M for later",
  or "Auto-clean is off"), and the hint that rejected channels can be brought back.
- **Kept**: the newest kept channels (`FindState.kept`, up to 100): name, handle, subscribers,
  median views, country, the keyword. A plain list or table; empty text when none.
- **Example data**: when the account is `unconfigured` (example data), a quiet hint that the
  search reads made-up AI channels. (`auth:status` tells you the state.)

## Words (all in `strings.ts`, English, plain)

Changes from the prototype, decided by the lead:
- The pause hint is **"Pausing stops at once. Everything found so far is saved."** (the pipeline
  stops mid-keyword and keeps what it read; the prototype's "finishes the keyword first" is no
  longer true).
- Error callouts by `run.error`: `no_youtube_key` "The team's YouTube key is missing or was
  refused. The owner can set it again."; `quota` "YouTube's daily limit is used up. It resets at
  midnight Pacific time."; `blocked` "YouTube stopped answering this computer. Wait a few hours,
  then try again."; `network` "Couldn't reach YouTube. Check the connection, then try again.";
  `crash` "The search stopped on an error. The details are in the log file."
- `find:start` problems, shown next to the button: `no_keywords` "Add keywords first.";
  `running` "A search is already running."; `no_youtube_key` as above; `no_python` "The search
  engine isn't set up on this computer yet."
Never show Python's own text except in the run log.

## How

- State: read `find:state` when the tab opens, then follow `find:changed`. Keep it in the existing
  store pattern (see `lib/store.ts`, `lib/live.ts` and how `sync:status` is followed).
- Dark only, desktop width; no light-theme or narrow checks. Use the design tokens
  (`--find` hue), the existing `@gratovo/ui` components and the prototype's CSS (port the
  `.fd-grid`, `.kw*`, `.yield`, `.log`, `.minis`, `.mini-stat` rules into the renderer's CSS).
- Accessibility: real buttons and labels; the list is a list; the log is a log region; the
  remove buttons are named "Remove <keyword>".
- Prototype mode is not touched.

## Tests

Vitest + Testing Library, like the existing renderer tests: each headline and button by state;
adding (split, counts, the message); Start here and Remove calling the right channels; the error
callouts; the kept list; the log region. Run `break-ui` over the screen with worst-case data
(long keywords and channel names, 500 keywords, a full log, zero kept) and fix what breaks.

Then look at it: `pnpm dev` (or the built app) on example data, dark, 1440 px, start a search and
watch it run; take a screenshot and save it to the scratchpad. Report what you checked.

Done when `pnpm lint`, `pnpm typecheck` and `pnpm test` pass. Don't commit; the lead reviews and
commits. Don't touch `CLAUDE.md` or `docs/migration-plan.md`.
